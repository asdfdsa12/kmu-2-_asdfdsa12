# 분석

## 사용한 메모리 사용량 측정 방법 및 기준

**메모리 = 추가로 할당한 힙 + 측정한 최대 스택 사용량**
 
| 구분 | 대상 | 방법 / 기준 |
|---|---|---|
| 힙 (직접 계산) | 병합 정렬의 임시 배열 | `n × sizeof(int)` = 4n Byte |
| 힙 | 힙 정렬, 퀵 정렬 | 추가 할당 없음, 0 Byte |
| 스택 (실측) | 병합·퀵의 재귀 호출 | 재귀 함수 진입마다 지역 변수의 주소를 읽어, 정렬 시작 시점의 기준 주소와의 차이의 최댓값을 기록 |
| 스택 (실측) | 힙 정렬 | 재귀가 없어서 `sift_down` 안의 지역 변수 주소로 같은 방식으로 측정(호출 체인의 스택 사용량) |
 
스택 값에는 반환 주소, 저장된 레지스터, 지역 변수와 매개변수가 쓰는 공간이 모두 포함된다.

스택 사용량은 컴파일러와 최적화 옵션에 따라 달라져, 다른 환경에서는 스택 값이 다르게 나올 수 있다.

최대 재귀 깊이도 함께 기록하였고, 퀵 정렬에서 Random 피벗은 실행마다 깊이가 달라지므로 전체 반복 중 최댓값을 사용하였다.

## 퀵 정렬의 피벗 선택에 대한 성능 차이

비교 횟수, 실행 시간, 메모리 사용량을 종합적으로 보았을 때, 중앙값 선택 방식이 가장 성능이 좋다고 볼 수 있다.

첫 번째 또는 랜덤 원소를 피벗으로 사용하는 경우, 극단적으로 치우친 값이 선택될 수 있고, 이는 정렬의 단계를 늘려 성능의 저하를 불러 일으킨다.

그러나, 중앙값을 선택할 경우, 극단적인 값을 선택할 확률이 크게 줄어들어 데이터의 분할이 절반에 가까워지기 때문에 평균적으로 가장 좋은 성능을 보인다.

랜덤 원소 선택 방식도 첫 번째 원소보다는 조금 더 좋은 성능을 보이는데, 이는 이미 정렬된 데이터를 예로 들 수 있다.

만약 이미 정렬된 데이터에서 첫 번째 원소를 피벗으로 선택할 경우, 최악의 시간 복잡도를 가지므로 이 경우에선 랜덤 원소를 선택하는 방식이 성능이 더 좋다고 볼 수 있다.

## 각 알고리즘의 시간, 공간 복잡도 차이

| 항목 | 힙 정렬 | 병합 정렬 | 퀵 정렬 |
|---|---|---|---|
| 시간 (최선) | Θ(n log n) | Θ(n log n) | Θ(n log n) |
| 시간 (평균) | Θ(n log n) | Θ(n log n) | Θ(n log n) |
| 시간 (최악) | Θ(n log n) | Θ(n log n) | Θ(n^2) |
| 공간 | O(1) (제자리, 반복문) | Θ(n) 임시 배열 + O(log n) 스택 | O(log n) 평균, O(n) 최악 (스택) |
 
세 알고리즘 모두 평균 시간 복잡도는 O(n log n)이며, 데이터가 2배가 되면 비교 횟수 또한 약 2배가 되는 것으로 확인할 수 있다.

최악의 경우 시간 복잡도는 퀵 정렬만이 O(n^2)이며, 이는 잘못된 피벗 선택으로 인한 극단적인 데이터 분할로 인해 일어난다.

힙 정렬의 공간 복잡도는 크기와 상관없이 352 Byte로 일정하여 O(1)이다.

병합 정렬의 공간 복잡도 Θ(n)은 힙이 4n Byte로 정확히 선형 증가한 결과이다.

퀵 정렬의 스택에 대한 공간 복잡도는 평균 O(n log n)이고, 최악에서 O(n)이 된다.
