# 분석

## 사용한 메모리 사용량 측정 방법 및 기준

**메모리 = 추가로 할당한 힙 + 측정한 최대 스택 사용량**
 
| 구분 | 방법 | 계산 기준 |
|---|---|---|
| 힙 (직접 계산) | 병합 정렬의 임시 배열 | `n × sizeof(int)` = 4n Byte |
| 힙 | 퀵 정렬 | 추가 할당이 없어 0 |
| 스택 (실측) | 재귀 함수 진입마다 지역 변수의 주소를 읽고, 정렬 시작 시점의 기준 주소와의 차이를 계산해 최댓값을 기록 | 반환 주소, 저장된 레지스터, 지역 변수와 매개변수가 차지하는 공간을 모두 포함 |
 
- 스택 사용량은 컴파일러와 최적화 옵션에 따라 달라져, 다른 환경에서는 스택 값이 다르게 나올 수 있다.
- 최대 재귀 깊이도 함께 기록하였고, 퀵 정렬에서 Random 피벗은 실행마다 깊이가 달라지므로 전체 반복 중 최댓값을 사용하였다.

|---|---|---|---|---|
| 1,000 | 8,742 | 13,636 | 12,540 | 11,694 |
| 2,000 | 19,448 | 27,432 | 25,661 | 24,971 |
| 4,000 | 42,851 | 60,927 | 62,004 | 57,330 |
| 8,000 | 93,609 | 129,263 | 131,822 | 119,805 |
| 16,000 | 203,253 | 275,926 | 281,440 | 261,124 |
| 20,000 | 260,738 | 350,046 | 348,922 | 338,274 |

두 알고리즘 모두 평균 시간 복잡도가 O(n log n)이기에, 비교 횟수가 n log n 꼴로 증가하는 것을 확인할 수 있다.

두 알고리즘 중에서, 병합 정렬이 퀵 정렬의 모든 피벗 선택 방식보다 비교 횟수가 적은 것을 확인할 수 있다.

이는, 병합 정렬은 구간을 정확히 반으로 나누지만, 퀵 정렬은 피벗에 따라 구간을 나누기 때문에, 정확히 반으로 나누는 경우가 드물어, 정렬에 더 많은 단계가 필요하기 때문이다.

### 두 알고리즘의 실행시간 차이 (ms)

| n | Merge | Quick (First) | Quick (Random) | Quick (Median3) |
|---|---|---|---|---|
| 1,000 | 0.0419 | 0.0246 | 0.0691 | 0.0213 |
| 2,000 | 0.1488 | 0.1008 | 0.1509 | 0.0998 |
| 4,000 | 0.3471 | 0.3168 | 0.2939 | 0.3149 |
| 8,000 | 0.8117 | 0.5672 | 0.7617 | 0.5779 |
| 16,000 | 1.4640 | 1.5549 | 1.6654 | 1.5523 |
| 20,000 | 2.3606 | 2.0250 | 2.1390 | 1.9913 |

위에서 비교 횟수를 확인하였을 때, 모든 구간에서 병합 정렬의 비교 횟수가 퀵 정렬보다 적었지만, 실행 시간의 경우는 그렇지 않은 것을 볼 수 있다.

이는, 병합 정렬의 병합 과정에서 많은 시간이 소요되었다는 것을 뜻한다.

병합 정렬은 구간 전체를 임시 배열에 복사하고, 병합 결과를 다시 기존 배열에 작성하기 때문에 병합 과정에서 많은 시간이 필요하게 된다.

반면, 퀵 정렬은 제자리 정렬이 가능하기 때문에 적은 시간 안에 비교와 교환을 마칠 수 있다.

### 두 알고리즘의 메모리 사용량 차이 (Byte)

| n | Merge | Quick (First) | Quick (Random) | Quick (Median3) |
|---|---|---|---|---|
| 1,000 | 5,200 (4,000 + 1,200) | 2,000 | 2,480 | 1,680 |
| 2,000 | 9,312 (8,000 + 1,312) | 2,000 | 2,560 | 1,600 |
| 4,000 | 17,424 (16,000 + 1,424) | 2,080 | 2,800 | 1,760 |
| 8,000 | 33,536 (32,000 + 1,536) | 2,400 | 3,200 | 1,840 |
| 16,000 | 65,648 (64,000 + 1,648) | 2,640 | 3,120 | 2,000 |
| 20,000 | 81,760 (80,000 + 1,760) | 2,800 | 3,200 | 2,160 |

병합 정렬은 병합을 위한 임시 배열 때문에 n에 비례하는 메모리를 사용한다.

해당 데이터는 int이기 때문에, n * 4에 달하는 메모리가 힙에 사용되고, 나머지 메모리는 재귀 스택의 메모리이다.

퀵 정렬은 제자리 정렬이기 때문에 재귀 스택만 사용하고, 이 또한 피벗 선택 방식에 따른 피벗 원소에 따라 달라지게 된다.

이 과정에서, 병합 정렬은 데이터를 정확히 절반으로 분할하지만, 퀵 정렬은 한 쪽으로 치우친 분할이 일어날 수 있기 때문에, 평균적인 메모리 사용량은 같은 데이터 크기에서 병합 정렬보다 더 많은 것을 확인할 수 있다.

## 퀵 정렬의 피벗 선택에 대한 성능 차이

비교 횟수, 실행 시간, 메모리 사용량을 종합적으로 보았을 때, 중앙값 선택 방식이 가장 성능이 좋다고 볼 수 있다.

첫 번째 또는 랜덤 원소를 피벗으로 사용하는 경우, 극단적으로 치우친 값이 선택될 수 있고, 이는 정렬의 단계를 늘려 성능의 저하를 불러 일으킨다.

그러나, 중앙값을 선택할 경우, 극단적인 값을 선택할 확률이 크게 줄어들어 데이터의 분할이 절반에 가까워지기 때문에 평균적으로 가장 좋은 성능을 보인다.

랜덤 원소 선택 방식도 첫 번째 원소보다는 조금 더 좋은 성능을 보이는데, 이는 이미 정렬된 데이터를 예로 들 수 있다.

만약 이미 정렬된 데이터에서 첫 번째 원소를 피벗으로 선택할 경우, 최악의 시간 복잡도를 가지므로 이 경우에선 랜덤 원소를 선택하는 방식이 성능이 더 좋다고 볼 수 있다.

## 두 알고리즘의 시간, 공간 복잡도 차이

| 항목 | 병합 정렬 | 퀵 정렬 |
|---|---|---|
| 시간 (최선) | Θ(n log n) | Θ(n log n) |
| 시간 (평균) | Θ(n log n) | Θ(n log n) |
| 시간 (최악) | Θ(n log n) | Θ(n^2) |
| 공간 | Θ(n) (임시 배열) + O(log n) (스택) | O(log n) 평균, O(n) 최악 (스택, 제자리 정렬) |

병합 정렬의 최악이 n log n인 것은 데이터 집합을 항상 절반으로 분할하기 때문이다.

퀵 정렬의 최악 n^2은 정렬된 입력과 First 피벗처럼 최소, 최대값이 피벗으로 잡혀 분할이 계속 치우칠 때 발생하는 이론값이다.

병합 정렬의 공간 Θ(n)은 힙이 4n Byte로 정확히 선형 증가한 결과이다.

퀵 정렬의 스택은 최악에서 O(n)이 되고, 이는 위에서 언급한 최악의 상황에서 발생하는 공간 복잡도이다.
