 # 생성 과정 분석

난수 100개를 생성하는 과정에서 중복으로 나온 값의 수는 5개로, 이것을 제외한 95개의 수가 배열 및 BST, AVL 트리에 저장되었다.

배열의 생성 과정에서 발생한 비교 횟수는 4,653회, BST의 생성 과정에서 발생한 비교 횟수는 643회, AVL 트리의 생성 과정에서 발생한 비교 횟수는 530회이다.

해당 비교 횟수들은 배열에 넣고자 하는 값이 이미 저장된 값인지 비교하며 발생한 비교 횟수이며, BST와 AVL 트리의 생성에는 삽입 위치를 찾기 위해 현재 노드의 값보다 큰지 작은지 비교하는 횟수가 추가로 발생한다.

이렇게 생성된 구조들의 길이 및 높이는 배열=95(저장된 값당 1), BST=13, AVL 트리=8로 나타났다.

생성된 BST와 AVL 트리의 높이가 서로 다르게 나타난 이유는, AVL 트리는 BST에서 노드 좌우의 균형을 맞추려하는 트리이기 때문이다.

그렇기에, 균형을 맞추기 위한 서브트리의 회전을 거치며 아래쪽에 있는 노드가 위로 올라오는 과정이 발생하며, 그 결과 BST와의 높이 차이가 발생하게 된다.

# 탐색 과정 분석

순차 탐색에서의 비교 횟수는 4,690회, BST 탐색에서의 비교 횟수는 434회, AVL 트리 탐색에서의 비교 횟수는 335회로 나타났다.

이를 BST와 AVL 트리의 높이랑 연결지어 보았을 때, 높이가 13인 BST의 비교 횟수가 높이가 8인 AVL 트리보다 더 높게 나타났다고 볼 수 있다.

그 이유로는, BST와 AVL 트리의 비교는 대소, 일치 비교를 아래 레벨로 내려가며 비교를 하게 되는데, 트리의 높이가 낮으면 그만큼 필요한 비교 횟수가 줄어들기 때문이다.

# 각 구조의 비용 분석

각 구조에서 생성과 탐색의 비용을 합한 값은, 배열 9,343(4,653 + 4,690)회, BST 1,077(643 + 434)회, AVL 트리 865(530 + 335)회로 나타났다.

배열과 트리 사이 큰 차이가 발생하는 이유는, 배열은 생성 과정에서 중복 검사를 할 때 모든 노드를 검사하게 되고, 탐색 과정에서도 모든 노드와 비교하기에 많은 비용이 발생한다.

그러나 트리의 경우, 생성 과정과 탐색 과정에서 모든 노드를 비교하는 것이 아닌 특정 경로의 노드만 비교하기에 상대적으로 적은 비용이 발생하게 된다.

종합하여, 생성 및 탐색에 필요한 비용의 경우, 모든 칸을 비교하는 배열 > AVL 트리보단 높이가 높은 BST > 가장 높이가 낮은 AVL 트리 순으로 비용이 높다고 볼 수 있다.
