# 그래프, 구현 방법, 알고리즘의 차이

## 그래프 성능 차이

먼저, 크루스칼 알고리즘에서의 각 그래프 성능 차이는 다음과 같다.

- 희소 그래프: 5796 Bytes 사용, 0.0189ms 소요
- 밀집 그래프: 27796 Bytes 사용, 0.1880ms 소요

밀집 리스트는 희소 리스트에 비해 약 4.80배 많은 메모리를 사용하였고,
실행 시간은 10배에 가까운 시간을 사용하였다.

이는 밀집 리스트에서의 간선이 희소 리스트 대비 6배인 600개가 되면서,
서로 인접한 정점을 저장하기 위한 노드의 수가 200개에서 1200개(무방향 그래프 고려),
간선의 정보를 저장하기 위한 구조체 배열의 칸이 100칸에서 600칸으로 증가하였기 때문이다.

그로 인해, 간선 정렬에 필요한 비용 또한 증가하여 실행 시간이 증가하게 되었다.

프림 알고리즘에서의 각 그래프 성능 차이는 다음과 같다.

- 희소 그래프: 11038 Bytes 사용, 0.0142ms 소요
- 밀집 그래프: 11038 Bytes 사용, 0.0197ms 소요

메모리 사용량은 두 그래프가 동일하고, 실행 시간은 밀집 그래프가 약 1.39배 더 소요되었다.

메모리 사용량이 동일한 이유는 간선 정보를 저장하기 위한 인접 행렬이 50(정점의 수) * 50 = 2500칸으로 동일하기 때문이다.

실행시간의 경우 행렬의 인덱스에 직접 접근하기 때문에 두 그래프 모두 비교적 소요 시간이 적고,
밀집 그래프의 경우 그래프 생성 시간이 더 소요되기에 전체 소요 시간이 더 높다.

## 구현 방법의 메모리 사용량 차이

인접 리스트와 인접 행렬의 메모리 사용량을 비교하였을 때, 희소 그래프는 인접 리스트의 사용량이 더 적지만,
밀집 그래프는 인접 행렬의 사용량이 더 많은 것을 알 수 있다.

이는, 인접 리스트는 간선의 개수에 비례하여 메모리 사용량이 증가하지만,
인접 행렬은 간선의 개수가 1개거나 2500(50 * 50)개여도 행렬 크기는 고정이라는 점이 작용한 것이다.

이를 통해, 간선의 개수가 적을땐 인접 리스트가,
간선의 개수가 많을땐 인접 행렬을 사용하는 것이 메모리를 효율적으로 사용 가능한 것을 알 수 있다.

## 알고리즘 실행 특성 차이

크루스칼 알고리즘은 간선을 가중치 오름차순으로 정렬하여 가중치가 작은 순서대로 사이클이 생기지 않도록 선택하는 방식으로,
간선을 선택하는 과정에서 사이클이 생기는지 확인하는 절차가 필요하고, 이를 Union-Find 자료구조를 사용해 구현하였다.
추가된 간선은 MST에 추가되고, 간선의 개수가 정점-1개가 될 때까지 반복한다.

프림 알고리즘은 MST에 포함된 정점과 포함되지 않은 정점끼리 연결되고, 가중치가 가장 작은 간선을 선택하는 방식으로,
선택된 간선과 정점을 MST에 추가, 모든 정점이 MST에 저장될 때까지 반복한다.

이러한 알고리즘의 특성 차이는 그래프의 간선 개수가 증가할수록 그 성능차이가 두드러지며,
프림 알고리즘의 성능이 크루스칼 알고리즘의 성능보다 앞선다는 것을 확인할 수 있다.

---
종합적으로 보았을 때, 그래프의 밀도가 높을수록,
즉 간선의 개수가 많은 밀집 그래프일수록 실행하는 데에 필요한 소요시간은
알고리즘과 구현 방법에 상관없이 공통적으로 증가하게 되나 인접 행렬과 프림 알고리즘 사용시엔 비교적 소요시간이 적다.
메모리 사용량의 경우에는 인접 행렬을 사용하는 경우엔 동일하며,
간선의 개수가 많아질수록 인접 행렬을 통한 구현의 효율이 더 높아짐을 알 수 있다.
